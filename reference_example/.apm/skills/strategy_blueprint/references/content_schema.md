# Content Schema (`content.json`)

Both `scripts/build_blueprint.py` (PDF) and `scripts/build_blueprint_docx.py` (Word) read the same JSON file. This is the contract between the interview and the build step — populate it as you finish each section of the interview rather than at the end. Once the file is filled in you can render either format, in either order, from the same source.

## Top-level keys

```jsonc
{
  "strategy_name": "Liquidity-Weighted Trend Strategy",  // required, used on the cover and as image captions
  "process_flow": {                                       // page-2 concept TOC. Optional — defaults to the canonical 3-step description.
    "intro": "The Process Flow:",
    "items": [
      {"label": "Strategy Definition",   "description": "Moving from intuition to a clear, testable hypothesis with an explicit source of returns."},
      {"label": "Feature Engineering",   "description": "Transforming raw data into meaningful, hypothesis-driven signals."},
      {"label": "Strategy Design",       "description": "Translating signals into portfolio decisions — selection, sizing, and timing — and validating results through robust testing and analysis."}

  "strategy_definition": { ... },

  "strategy_design":      { ... },
  "conclusions":          { ... },

}
```

## Validation rules the build script enforces

- `strategy_name` is non-empty.
- Every H1 / H2 listed in `references/structure_outline.md` is present in `content.json`. Missing keys cause the script to print a heading + `_Pending — see TODO list._` block and **append the heading path to the TODO list** that gets dumped to stderr at the end.
- `strategy_score.rows[*].weight` values sum to exactly 100.0 (± 0.05 tolerance). Otherwise the build aborts with a clear error.
- All image paths must exist on disk relative to the project root. Missing images are rendered as a captioned grey placeholder with the literal filename printed inside, so the document still builds.
